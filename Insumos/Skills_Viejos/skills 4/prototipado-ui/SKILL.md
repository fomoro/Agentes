# Prototipado de interfaz

Convierte una necesidad funcional confirmada en una experiencia validable con el menor costo de construcción necesario.

## Método

1. Confirma usuario, objetivo, flujo principal, contenido y estados que deben validarse.
2. Define jerarquía, navegación y comportamiento responsive antes del detalle visual.
3. Construye un prototipo autocontenido cuando la solicitud requiera abrirlo sin instalación.
4. Usa datos demostrativos claramente identificados y cubre los estados relevantes.
5. Verifica navegación, legibilidad, foco, contraste y tamaños táctiles.

## Reglas

- Diseña mobile-first cuando el uso móvil forme parte del alcance.
- Prioriza componentes y utilidades del sistema visual o framework acordado antes de crear estilos propios.
- Mantén HTML semántico, etiquetas comprensibles y foco visible.
- No presentes datos demostrativos como métricas, clientes o comportamientos confirmados.
- El prototipo no define contratos, persistencia ni reglas funcionales.

## Criterio de cierre

- El flujo priorizado puede recorrerse de principio a fin.
- Los estados solicitados están representados y los datos ficticios son reconocibles.
- El artefacto abre y funciona en el entorno acordado sin dependencias no informadas.
